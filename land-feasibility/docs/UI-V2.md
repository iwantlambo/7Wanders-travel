# 介面改版契約 UI-V2.md（2026-09-28）

**本檔覆蓋 SPEC.md 第 8 節與 REFACTOR.md 第 2～4 節。衝突時以本檔為準。**
SPEC.md 第 1 節（執行環境鐵則）、第 3 節（TD.V 信心包裝）、第 7 節（引擎契約）**維持有效，引擎完全不動**。

---

## 0. 為什麼要改

現在的介面把 **M1～M8** 做成左側導覽列。那八個代號是當初規劃「這個題目要解哪幾塊」的**思考階段**，
不是使用者的操作流程。使用者打開工具看到 `M1 土地基本資訊 / M2 產權地雷 / M3 法規檢討…`
根本不知道這是什麼、也不知道該從哪裡開始。

**新的心智模型只有一句：輸入地號等基本資料，右邊就把該知道的全部算出來。**

使用者是經營建設開發公司的專業人士。他要的是速度，不是導覽。

---

## 1. 硬性要求

1. **白底。** 淺色主題，不要深色。移除 `prefers-color-scheme: dark` 整段，不做主題切換。
2. **單一頁面，沒有導覽列、沒有分頁、沒有模組代號。**
   介面上**任何地方都不准出現 `M1`～`M8` 這種代號**，也不要出現「模組」這個詞。
   引擎內部的 `TD.V` key（`m3.far` 等）維持不變，但**不得顯示給使用者**；
   明細抽屜要顯示**中文標籤**（例如「容積率」），不是 key。
3. **左邊輸入、右邊結果。** 輸入一改，右邊立刻重算。
4. 刪除簡報模式（`js/ui/present.js`）。刪除設定頁，設定改成右上角選單裡的小視窗。
5. 其餘鐵則不變：純靜態、完全離線、ES5、無 CDN、無 `fetch`、手寫 inline SVG。

## 2. 版面

```
┌───────────────────────────────────────────────────────────────┐
│ 土地開發可行性評估        [專案 ▾]              [報告] [⋯]    │  ← 頂列 48px
├──────────────────┬────────────────────────────────────────────┤
│ 輸入（360px）    │ 結果（流式，由上往下）                      │
│ sticky           │                                            │
│                  │  ① 出價上限（大數字）                       │
│ 基地             │  ② 一頁摘要                                 │
│ 謄本 ▸           │  ③ 風險與待確認                             │
│ 開發方式 ▸       │  ④ 敏感度                                   │
│ 進階假設 ▸       │  ⑤ 壓力測試                                 │
│                  │  ⑥ 明細（可收合）                           │
└──────────────────┴────────────────────────────────────────────┘
```

- `≥1100px`：兩欄 `360px / 1fr`，左欄 `position: sticky`。
- `900～1099px`：兩欄 `320px / 1fr`。
- `<900px`：單欄堆疊，輸入在上，左欄不再 sticky、不再限高。
- 頁面最大寬度 1500px 置中。

實作對應的是 `@media (max-width:1099px)` 與 `@media (max-width:899px)`（界線含在小的那一側），
而且這兩段**必須排在 `.pane-in` 的基礎規則之後**，否則同選擇器同權重會被後面的規則蓋掉。

## 3. 左欄：輸入

四個區塊。第一塊永遠展開，其餘預設收合（`<details>` 或自製收合，需記住展開狀態於 `localStorage`）。

**3.1 基地**（永遠展開）
縣市、行政區、段小段、地號（可增刪列，每列：地號／面積 ㎡／權利範圍）、
使用分區（下拉，依縣市帶出）、臨路寬度 m、臨路條數、角地、基地寬 m、基地深 m、
所有權人數、最大持分分母、既有建物屋齡、既有建物樓地板 ㎡。

**3.2 謄本**（收合）
一個 textarea ＋「解析」按鈕。解析結果用一張小表列出：欄位／抓到的值／原文片段／［套用］。
抓不到的另列一張「未解析」清單。上方**最多一行**操作提示，不要說明謄本怎麼申請。

**3.3 開發方式**（收合）
制度單選（都市更新／危老重建／不走更新危老）＋ 該制度可用的獎勵項目多選。
每個項目一列：勾選框／名稱／成數（可改）／取得成本／時程／代價。
下方一個「套用最佳組合」按鈕。

**3.4 進階假設**（收合，四個小群組）
- 量體：免計容積比、銷坪率、公設比、平均每戶坪數、每車位樓地板、層高
- 售價：使用示範比價資料（勾選）、CSV 貼上、人工指定單價、預售溢價、每月去化戶數
- 成本：營建類型／單價、土建融成數與利率、管銷、廣告、設計監造、稅率
- 時程與目標：規劃期、工期、交屋期、預售起始月、目標 IRR、目標淨利率

## 4. 右欄：結果

**① 出價上限**（最上方，最大）
- 主數字：土地出價上限（總價），字級 `clamp(34px, 4vw, 52px)`。
- 副排：每坪土地單價｜走人價｜達成 IRR｜達成淨利率。
- 一個短標籤說明哪一條在綁：`IRR 條件在綁` 或 `淨利率條件在綁`。
- **資料不足時**（例如沒有面積或沒有比價資料）：顯示「尚無法計算」與**缺什麼**的短清單，
  不可顯示 0 或 NaN，也不可憑空生出數字。

**② 一頁摘要**（一張密集表，兩欄式 label／value，不要卡片堆）
產權燈號、建蔽率、容積率、基準容積（坪）、容積獎勵（％ 與坪）、總容積（坪）、
可售坪、戶數、車位數、地上層數、成交單價（萬/坪）、總銷、總成本（不含地）、稅後淨利。
每個數字照舊用 `TD.ui.num` 輸出，保留信心徽章，可點開明細。

**摘要的面積固定以坪表示**，不隨 `⋯` 選單的面積單位切換（欄位標籤本來就寫成「坪」）。
這是刻意的，但不可以是無聲的：區塊標題右側要標「固定以坪表示」，
單位切換只影響下方第 ⑥ 節的明細。

**上游算不出來時，下游那一格不得印數字。** 引擎為了讓管線跑完，在上游為 `null` 時
某些下游欄位會回落成 0（例如基準容積為 `null` 時的獎勵樓地板與總容積，
或總銷為 `null` 時以回落粗估總銷推出來的總成本）。那個 0 不是答案，是算不出來。
介面層必須自己守門：驅動值為 `null` 就印「—」、**不掛信心徽章**、把缺什麼寫進 `title`。
同一條規則要同時套在一頁摘要、第 ⑥ 節的成本結構合計列、以及該區塊收合標題右側的數字，
三處不得互相矛盾。

**③ 風險與待確認**
- 產權：燈號＋旗標逐列（名稱／原因／可不可解）。
- 法規：無法計算的項目逐列（項目／需要什麼資料）。
- 資料：待查證數量＋未複核數量，一個「開啟報告逐項確認」按鈕。

**④ 敏感度**：龍捲風圖＋表（項目／變動／低端／高端／擺動）。

**⑤ 壓力測試**：四列表（情境／淨利率／IRR／判定），不通過的列紅底。
表尾固定輸出 `ctx.m8.stressRule`：「通過」兩個字有重量，而那個門檻是本系統自訂的，
定義必須跟著表格一起出現（報告端共用同一份，不要重複印第二次）。

**⑥ 明細**（全部預設收合）
法規檢討明細、容積獎勵組合排行（前 8）、量體明細、比價明細＋散佈圖、成本結構、現金流圖＋逐月表。

## 5. 視覺

淺色系統，乾淨、對比清楚、不要裝飾。

```
--bg:#f7f8f8   --panel:#ffffff   --ink:#111827   --ink-2:#4b5563   --ink-3:#9ca3af
--line:#e5e7eb --line-2:#d1d5db
--accent:#0f766e  --accent-soft:#ecfdf5  --accent-ink:#0b5a54
--red:#b42318 --red-soft:#fef3f2 --amber:#b54708 --amber-soft:#fffaeb
--green:#067647 --green-soft:#ecfdf3 --violet:#5925dc --violet-soft:#f4f3ff
```

- 卡片：白底、1px `--line` 邊、圓角 8px、**不要陰影**（或極淡）。
- 區塊標題：13px、600、`--ink-2`、字距 .02em。不要 emoji、不要裝飾線。
- 表格：`th` 11px `--ink-3`；`td` 13px；padding `5px 8px`；列分隔線 `--line`。
- 數字一律 `font-variant-numeric: tabular-nums`。
- 信心徽章維持現有五色，但縮到 9px、不要邊框、只用淺底色。
- 輸入元件：高 30px、1px `--line-2` 邊、圓角 6px、focus 時邊框轉 `--accent`。
- **`.note` 這種整段文字框，全頁最多出現兩處**（量體簽證警語、資料不足提示）。

## 10. 驗收

- `bash tools/checkall.sh` 全過；`node tools/smoke.js` 全過且 ≥17 項。
- 瀏覽器實測（白底）：輸入面積／分區改變時右欄即時更新；
  1440×900 下不捲動即可看到出價上限與一頁摘要；1280 與 900 寬無水平捲動。
- 清空所有輸入時，右欄顯示「尚無法計算」與缺項清單，無 NaN、無 0 冒充。
- 打字時不被重繪打斷（焦點與游標位置保留）。打字後約 200ms 重算；
  中文輸入組字中（`isComposing`）不重算。
- 頂列「報告」與 `Ctrl`／`Cmd` + `P` 都要能開出報告，內容含免責聲明；
  報告開不起來時**不得列印**，也不得在畫面上留下遮罩。
