## 0. 使用者是誰（決定一切）

使用者是**經營建設開發公司的專業人士**。地政、法規、財務他都比這個工具熟。
他要的是**自動化掉流程**，把三到七天壓成幾小時。他不需要任何人教他這行怎麼做。

因此：

**刪掉所有「說明為什麼」的文字。** 包括但不限於：
- 「這一步在算什麼」「這個模組的價值在於…」「這是整條鏈上最被低估的一塊」
- 「真正的題目不是有哪些獎勵，而是…」「這是最敏感的資料，外部拿不到」
- 「謄本怎麼來：第一類謄本須由所有權人本人親自向地政事務所申請…」
- 「狀態的判準：未填＝…」「這條列不是進度條，是責任清單」
- 三個設計原則那張卡、AI 契合度、護城河、利益衝突等等一切產品論述
- 任何解釋名詞、解釋方法論、解釋為什麼要這樣算的句子

這些是當初寫給開發者看的簡報材料，不是工具的一部分。專業使用者看到會覺得吵。

**保留（這些不是註解，是資料）：**
- 欄位標籤、單位、數字本身
- 信心徽章（高／中／低／待查證／輸入）與法源字串 —— 這是資料出處，不是說教
- 抽屜（drawer）裡的算式、法源、備註 —— 那是**點開才看得到**的，不佔畫面
- M5 的建築師簽證警語，壓成**一行**
- 報告（report）的免責聲明 —— 那是對外交付文件，有法律作用
- 表格裡的 `tradeoff`／`note` 等**逐列的短欄位**（那是每一項的屬性，不是段落）

判準：**一句話如果拿掉之後，專業使用者仍然知道這個數字是什麼、怎麼來的，就拿掉。**

## 1. 移除三個客戶版本（A 地主／B 銀行／C 建商）

改成單一引擎，任何人打開都是同一套。

**刪除檔案**
- `js/data/editions.js`
- `js/engine/edition.js`
- `js/ui/views-edition.js` 的 `edA`／`edB`／`edC` 三個檢視（`settings` 保留，檔案更名為 `js/ui/views-settings.js`）

**index.html**
- 移除 `#editionSwitch` 整塊與其三個按鈕
- 移除 `js/data/editions.js`、`js/engine/edition.js` 的 `<script>`
- `js/ui/views-edition.js` 改為 `js/ui/views-settings.js`

**專案結構**
- `p.edition` 欄位移除。`importJSON` 遇到舊檔案要能吃下並忽略該欄位（不可報錯）。
- `TD.store.defaults()` 與 `sample()` 同步移除。

**pipeline**
- 不再產生 `ctx.ed`。`ctx.edition` 移除。

**把原本 edition 裡真正有用的東西併回 M8**（它們與客戶身分無關，是每個案子都要看的）：
- **壓力測試**四項：利率 +2 個百分點、售價 −15%、工期 +9 個月、去化 −40%，
  各自輸出 `margin`、`irr`、`verdict`（通過／警示／不通過）。放 `ctx.m8.stress`。
- **走人價** `ctx.m8.walkAway`：以 `targetIrr + 3 個百分點` 回推的土地上限。
- 其餘（三條變現路徑、擔保價值、可貸額度、法源可追溯性面板）一律刪除。

**簡報模式**
保留，但只有**一套**投影片，不再分版本。投影片定義從 `editions.js` 移到 `js/ui/present.js` 內部。
底部控制列移除 A／B／C 切換鈕。投影片內容：出價上限 → 獎勵組合前三名 → 敏感度 → 什麼情況下會賠錢 → 複核缺口。
每張只有標題與數字，**不要旁白**。
