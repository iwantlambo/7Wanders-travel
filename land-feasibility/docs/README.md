# 土地開發可行性評估

**左邊輸入地號等基本資料，右邊就把該知道的全部算出來。**

單一頁面、白底、純靜態網頁。解壓縮後雙擊 `index.html` 就能用。
沒有伺服器、沒有帳號、沒有任何網路請求，所有運算都在你自己的瀏覽器裡完成。

---

## 1. 為什麼要有這個東西

土地評估的現況是：開發部拿到一個地號，要花**三到七天**，跨建築師與財務兩邊來回，
才能生出一份可以進投決會的初判。等到數字出來，好地早就被別人買走了。
速度在這個產業直接等於錢。

這個工具的目標是把那三到七天壓到**幾小時**。它不取代建築師簽證，也不取代估價報告，
它回答的是更前面那個問題：**這塊地值不值得我派建築師與財務進去。**

判斷的重點不是算得多漂亮，而是把「哪裡算不出來」明確攤在桌上。
系統附的法規與成本數值全部是**未經查證的種子資料**，正式使用前必須逐項核對，
清單見 `docs/DATA-VERIFICATION.md`。

## 2. 三個設計原則

### 原則一：不對稱精度陷阱

九成正確在這個領域不是好成績，是危險。漏掉一條但書、一塊畸零地，
就足以讓幾億的案子做錯決策。**算錯一次的損失遠大於算對五十次省下的時間。**

所以介面不是「給一個乾淨的答案」，而是「標示不確定、強制人工複核」：

- 每一個對外顯示的數字都掛**信心等級**（法規明文 `高` ／ 公開資料推算 `中` ／ 假設驅動 `低` ／ 種子資料 `待查證` ／ 使用者輸入 `輸入`）。
- 每一個數字都點得開，抽屜會顯示它的**中文名稱、法源、算式與備註**，讓複核者能自己手算驗證。
  抽屜顯示的是中文標籤，不是引擎內部的識別字。
- 算不出來的一律顯示「—」或「尚無法計算」並列出缺什麼，
  **絕不假裝算得出來、絕不回 NaN、絕不用 0 假裝是答案、不用預設值填補**。
  上游算不出來時，即使引擎因為內部回落機制算出了一個下游數字，介面也會擋掉不顯示。
- 示範專案跑完共產生 56 個掛牌數值，其中 **43 項需要人工複核，預設全部未複核**。
  這個比例是刻意的，不是沒做完。

### 原則二：護城河在髒活不在模型

財務模型本身不難，難的是把台灣的分區管制、畸零地規則、容積獎勵辦法逐條、逐縣市、逐年度地餵進來並維持正確。
所以資料層（`js/data/*.js`）寫成一格一格、附法源、附查證指引的純資料檔，
目標是**讓人容易逐條擴充與查證**，不是寫得聰明。條號查不到一律寫「待查」，
**寧可寫「待查」也不要編一個條號** —— 編出來的條號會讓複核者誤以為已經查過。

### 原則三：利益衝突是架構問題不是承諾問題

這套工具的賣方立場本身就是最大的障礙：憑什麼相信你不會把我在看哪塊地、出價多少，
轉手告訴競爭對手。口頭保證解決不了這件事，**架構才能**。

系統完全在瀏覽器內運算：沒有伺服器、沒有帳號、沒有 API 呼叫、沒有分析套件、沒有外部 CDN。
全專案不存在 `fetch`、`XMLHttpRequest`、`WebSocket` 與 `sendBeacon`（`tools/checkall.sh` 每次都會檢查）。
資料只存在你自己的瀏覽器 localStorage 與你自己匯出的 JSON。
**你可以拔掉網路線再跑一次驗證這句話。**

## 3. 計算鏈：從地號到出價上限

引擎分成八段依序跑：
**土地基本資訊 → 產權 → 法規檢討 → 容積獎勵（粗估）→ 量體 → 收入 → 容積獎勵（用真實單價重算）→ 成本 → 財務回推**。
任何一段丟出例外，管線會接住、把那一段標成錯誤，然後**繼續跑後面的**，畫面不會整片掛掉。

這八段是**引擎的內部結構，不是使用者的操作流程**。介面上不會出現它們的代號，
使用者只會看到「左邊填、右邊出」。這一節寫給要擴充或複核程式的人看。

| 段 | 做什麼 | 最容易出錯的地方 |
|---|---|---|
| 土地基本資訊 | 地號列合併、面積、使用分區、基地寬深與臨路、所有權人結構、既有建物，以及登記謄本全文解析 | 謄本沒有標準電子格式；只有**第一類謄本**才有完整所有權人與他項權利，第二類會遮罩，判讀不了產權地雷 |
| 產權 | 偵測祭祀公業、未辦繼承、日治時期名義人、限制登記、共有結構與土地法第 34 條之 1 同意門檻 | 這些問題處理時間動輒數年，卻完全不會出現在試算表上 |
| 法規檢討 | 建蔽率、容積率、建築面積、基準容積樓地板，加上畸零地、臨路、退縮、停車等檢核 | 圖資類檢核（地籍圖、細部計畫但書）程式算不出來，一律標「算不出來」並寫明需要什麼資料 |
| 容積獎勵 | 列舉都更／危老可申請的獎勵組合、逐項成數、取得成本、時程與代價，排出淨效益前幾名 | 各項獎勵有互斥與封頂規則；跑兩次是刻意的，第一次還沒有真實單價，第二次才用得上 |
| 量體 | 容積樓地板、免計容積、地上總樓地板、地下室、可售坪、戶數、車位、層數、高度 | **沒有法律效力**，必須由開業建築師簽證。信心一律標「低」並掛固定警語 |
| 收入 | 比價（特徵價格回歸／加權／人工指定）、成屋與預售單價、房屋與車位收入、總銷、去化月數 | 內建案例是合成資料；沒有樣本時**直接拒絕估價**，整條鏈回 `null`，不會回落成一個好看的數字 |
| 成本 | 營建（地上／地下）、管銷、廣告、設計監造、融資利息、稅費，以及逐月動撥 S 曲線 | 整個系統最不可靠的一段：營建單價與融資條件沒有外部來源，建商自己的實績一定比預設值準 |
| 財務回推 | 以目標 IRR 與目標淨利率兩條路徑回推土地出價上限、取小者，另出走人價、敏感度、壓力測試、三情境與逐月現金流 | 求不出解時回 `null` 並說明原因；壓力測試的判定門檻是本系統自訂，不是銀行授信準則 |

基準案（臺北市大安區、商三、660 ㎡）的定錨數字：
`660 ㎡ × 5.6 = 3,696 ㎡` 基準容積、可售 `1,574.1` 坪、出價上限 `12.92 億元`、達成 IRR `15.00%`。
這四個數字被 `tools/smoke.js` 釘住，改壞了會立刻紅。

## 4. 介面：一頁、兩欄

```
┌───────────────────────────────────────────────────────────────┐
│ 土地開發可行性評估      [專案 ▾] [＋]          [報告] [⋯]     │  ← 頂列
├──────────────────┬────────────────────────────────────────────┤
│ 輸入（左，sticky）│ 結果（右，流式，由上往下）                  │
│                  │                                            │
│ 基地             │  ① 出價上限（大數字）                       │
│ 謄本 ▸           │  ② 一頁摘要                                 │
│ 開發方式 ▸       │  ③ 風險與待確認                             │
│ 進階假設 ▸       │  ④ 敏感度                                   │
│                  │  ⑤ 壓力測試                                 │
│                  │  ⑥ 明細（預設收合）                         │
└──────────────────┴────────────────────────────────────────────┘
```

- 沒有導覽列、沒有分頁、沒有簡報模式、沒有設定頁。
- **輸入一改，右邊立刻重算**（打字後約 0.2 秒），重繪時保留焦點與游標位置。
- 版面：`≥1100px` 兩欄 360px／其餘；`900～1099px` 兩欄 320px／其餘；`<900px` 單欄堆疊，輸入在上。
- 收合狀態記在 `localStorage`，下次打開還在。

### 左欄：輸入

| 區塊 | 內容 |
|---|---|
| **基地**（永遠展開） | 縣市、行政區、段小段、地號列（可增刪，每列：地號／面積 ㎡／權利範圍）、使用分區（依縣市帶出）、臨路寬度與條數、角地、基地寬深、所有權人數、最大持分分母、既有建物屋齡與樓地板 |
| **謄本**（收合） | 全文貼上框 ＋「解析」。結果用一張小表逐列列出：欄位／抓到的值／**原文片段**／單列套用鈕，另有「未解析」清單 |
| **開發方式**（收合） | 制度單選（都市更新／危老重建／不走更新危老）＋ 該制度可用的獎勵項目多選，每列有成數、取得成本、時程、代價；下方「套用最佳組合」 |
| **進階假設**（收合） | 四小群：量體（免計容積比、銷坪率、公設比、每戶坪數、每車位樓地板、層高）、售價（示範比價資料、CSV 貼上、人工單價、預售溢價、每月去化戶數）、成本（營建類型與單價、土建融成數與利率、管銷、廣告、設計監造、稅率）、時程與目標（規劃期、工期、交屋期、預售起始月、目標 IRR、目標淨利率） |

### 右欄：結果

| 區塊 | 內容 |
|---|---|
| **① 出價上限** | 主數字（土地總價）＋ 每坪土地單價／走人價／達成 IRR／達成淨利率，並標明是 IRR 條件還是淨利率條件在綁。**資料不足時顯示「尚無法計算」與缺什麼的清單**，不顯示 0 或 NaN |
| **② 一頁摘要** | 產權燈號、建蔽率、容積率、基準容積、容積獎勵、總容積、可售坪、戶數、車位數、地上層數、成交單價、總銷、總成本（不含地）、稅後淨利。**面積固定以坪表示**（標題右側有註記），面積單位切換只影響下方明細 |
| **③ 風險與待確認** | 產權燈號與旗標逐列（名稱／原因／可不可解）、法規算不出來與不通過的項目逐列（項目／需要什麼資料）、複核進度（需複核／已複核／未複核／其中待查證）＋「開啟報告逐項確認」 |
| **④ 敏感度** | 龍捲風圖 ＋ 表（項目／變動／低端／高端／擺動），標題右側標出最敏感的那一項 |
| **⑤ 壓力測試** | 四情境表（情境／淨利率／IRR／判定），不通過的列紅底，表尾一行寫明**判定門檻的定義（本系統自訂）** |
| **⑥ 明細**（預設全收合） | 法規檢討明細、容積獎勵組合排行（前 8，點列即套用）、量體明細＋樓層堆疊示意、比價明細＋散佈圖、成本結構＋S 曲線、現金流圖＋逐月表 |

### 頂列與 ⋯ 選單

| 元件 | 做什麼 |
|---|---|
| 專案下拉 ／ ＋ | 切換已存的專案 ／ 建立新專案 |
| 報告 | 開啟可列印報告（下方單獨說明）。`Ctrl`／`Cmd` + `P` 會先開報告再列印 |
| ⋯ | 匯出專案 JSON ／ 匯入專案 JSON ／ 匯出全部專案 ／ 複製此專案 ／ 載入示範專案 ／ **面積單位（坪 ｜ 平方公尺，只改顯示，內部一律以平方公尺運算）** ／ 資料版本 ／ 覆寫與複核紀錄 ／ 刪除此專案 |

### 數值明細抽屜（點任何帶徽章的數字都會開）

這是原則一的主要介面。內容：**中文名稱**、目前值、信心等級、法源出處、算式文字、備註，加上：

- **覆寫輸入框**：填一個數字按「套用覆寫」，該值會改成你的數字、信心標為「輸入」，備註前面加上原值。按「清除覆寫」還原。
  覆寫不會重算下游，所以右欄上方會出現一條提示 —— 這件事必須看得到。
- **已複核勾選 ＋ 複核備註**：勾了才會從複核進度的待辦數扣掉。
- **複製法規名稱**：法規深連結會隨改版失效，所以系統只給全國法規資料庫首頁連結，另外提供這顆按鈕讓你把法規名稱貼到官網自己搜。

### 報告

可列印、可交付，覆蓋在主畫面上，`Esc` 或「關閉」退出。順序：
封面 → 出價上限 → 一頁摘要 → 風險與待確認 → 敏感度 → 壓力測試（含門檻定義）→ 走人價與損益兩平緩衝 →
法規檢討明細 → 容積獎勵組合 → 量體明細 → 比價明細 → 成本結構 → 現金流（逐月明細一律展開）→
**逐項複核清單（可直接勾選）** → 顯示覆寫紀錄 → **免責聲明**。

**未複核時仍然顯示報告內容。** 擋掉只會讓人繞過工具去用 Excel，
所以做法是把複核清單印進報告裡。
列印時只印報告本文；在瀏覽器的列印對話框選「另存為 PDF」即可交付。
**信心徽章列印出來一樣看得到，這是刻意的** —— 交出去的文件必須帶著它自己的不確定性。
報告開不起來時不會列印（否則會印出一張沒有免責聲明的紙）。

## 5. MVP 範圍與明確不做的事

### 這一版只做

- **只做臺北市。** 13 個分區的種子值、畸零地表、停車換算與退縮欄位。其他縣市留了 `_template` 空殼。
- **只吃你自己貼上的謄本文字。** 不連網、不代查、不代為申請。
- **只做初判。** 輸出是「值不值得往下做」，不是估價報告、不是建築師簽證、不是法律意見。

### 明確不做

| 不做 | 為什麼 |
|---|---|
| 任何網路請求、帳號、雲端同步 | 原則三。這是架構承諾，不是功能取捨 |
| 地籍圖、都市計畫圖、日照模擬、套繪 | 需要圖資與專業軟體；缺了就標「算不出來」，不用假算式填補 |
| 出具估價報告或取代建築師簽證 | 法律上做不到，也不該做 |
| 多人協作、權限、稽核伺服器 | 與原則三直接衝突 |
| 任何 LLM 或 API 呼叫（`js/lib/ai.js` 刻意不建立） | 同上；且本系統的價值在可追溯，不在生成 |
| 深色模式、主題切換 | 白底一種就夠，少一組要維護的顏色 |
| 多檢視、分頁、依對象切換的客戶版本 | 使用者要的是速度不是導覽。同一份資料只有一種呈現 |

### 為什麼「算到量體就停」是錯的

有人會說：算到坪數就夠了，大家自己心裡有數。這個判斷有兩個錯：

1. **量體是法律效力的邊界，不是執行的邊界。** 量體之所以信心一律標「低」、之所以掛固定警語，
   是因為它必須建築師簽證才有效力。但「沒有法律效力」跟「不該算」是兩件事 ——
   停在量體只是把不確定性留在原地，沒有把它往前推進。
2. **坪數不是決策，出價才是決策。** 知道能蓋 1,574 坪，回答不了「這塊地我出 13 億還是 15 億」。
   從坪數到出價之間還隔著單價、成本，以及反解土地價的那條方程式，
   而那三段恰恰是誤差最大、最需要標信心等級的地方。
   **只有走到財務回推才回答得了出價上限。** 停在量體等於把最危險的一段留給 Excel 和直覺，
   而那正是原則一要防的事。

## 6. 已知限制與不可迴避的風險

請在對外使用前讀完這一節。

1. **種子資料未查證。** `js/data/*.js` 內所有法規與成本數值都是開發者依一般認知先填的，
   **尚未與官方條文逐字核對**，一律標「待查證」。示範案 56 個數值裡有 43 項需要複核。
   逐項清單見 `docs/DATA-VERIFICATION.md`。
2. **量體沒有法律效力。** 可售坪、戶數、層數是體積估算，不是建築設計。
   日照、防火間隔、退縮細節與細部計畫但書無法程式化，必須由開業建築師簽證。
3. **成本資料外部拿不到。** 營建單價未接政府電子採購網決標資料，融資條件未接銀行實際報價，
   物價指數接口空著。成本是整個系統最不可靠的一段，建商自己的實績數字一定比預設值準。
4. **只做臺北市。** 換縣市就要自己填一份分區管制資料，而各縣市的檔案格式（PDF、掃描檔、HTML）差異極大，
   這是擴充成本的主要來源。
5. **實價登錄是合成範例。** 內建 14 筆比較案例是程式產生的假資料，係數杜撰。
   匯入真實資料前，任何價格數字都不得對外引用；沒有樣本時系統會拒絕估價，整條鏈回 `null`。
6. **資料只存在這台瀏覽器。** 換瀏覽器、換電腦、清除網站資料、無痕模式都會讓專案消失。
   **請養成用「⋯ → 匯出專案 JSON」備份的習慣。** 儲存不可用時系統會退到記憶體模式並在右欄警告。
7. **謄本解析是正則比對，不是理解。** 排版一變就可能漏抓。
   每一列都附原文片段就是為了讓你逐列核對，不要跳過。
8. **壓力測試的「通過」是本系統自訂的門檻**，不是銀行授信準則。定義印在表格下方與報告裡。
9. **系統不判斷可行性，只判斷值不值得往下查。** 紅燈不代表一定不能做，綠燈更不代表可以簽約。

## 7. 使用流程走一遍

1. **新建專案**（頂列「＋」）。想先看示範案就用「⋯ → 載入示範專案」（臺北市大安區、商三、660 ㎡）。
2. **填基地**：左欄第一塊。縣市、行政區、段小段、地號與面積、使用分區。
   填到這裡右欄的出價上限通常就出得來了 —— 其餘欄位是把它算得更準，不是讓它開始算。
3. **貼謄本**（可選）：展開「謄本」，把你自己申請到的**第一類**土地與建物登記謄本文字整段貼進去，按「解析」。
   對照表會逐列列出抓到的值與原文片段。**逐列核對後**再套用。抓不到的看「未解析」清單，自己補到基地欄位。
4. **看右欄第三塊「風險與待確認」**：產權亮紅旗就先停下來找地政士，別急著往下算價格；
   法規那張表告訴你還缺什麼圖資才算得出來。
5. **選開發方式**：展開「開發方式」，選制度（都更／危老／不走），勾獎勵項目，或直接按「套用最佳組合」。
   也可以在右欄明細的「容積獎勵組合排行」點任何一列直接套用。
6. **換掉假資料**：展開「進階假設」。
   **先把內建合成比價案例換成真實實價登錄資料**（CSV 貼上），
   再**把營建單價與融資條件換成你自己的實績或銀行報價** —— 這一步對結果影響最大。
7. **設目標**：同樣在「進階假設」裡設目標 IRR 與目標淨利率，看出價上限怎麼動。
8. **讀敏感度與壓力測試**：哪一項假設最會咬人、什麼情況下會賠錢。
9. **逐項複核**：把每個帶徽章的數字點開，讀法源與算式，需要就覆寫，複核完勾「已複核」。
   複核進度的未複核數要降到你能接受的程度。
10. **報告**：頂列「報告」，確認複核清單的內容你能接受，然後「列印／另存 PDF」交付。

**收尾一定要做的事**：用「⋯ → 匯出專案 JSON」存一份備份。資料只在你的瀏覽器裡。

## 8. 檔案結構

```
index.html              版面骨架與 script 載入順序
assets/app.css          全部樣式（單一淺色主題，無深色規則）
js/lib/                 fmt（格式化）、value（信心包裝與等級）、math（統計與財務）、store（專案儲存）
js/data/                zoning、bonus、cost、comps、laws        ← 查證與擴充都改這裡
js/engine/              八段計算 ＋ pipeline                     ← 純函式，不碰 DOM，可在 Node 測
js/ui/                  common（共用元件與中文化）、inputs（左欄）、
                        results（右欄 ①～⑤）、details（右欄 ⑥）、report（可列印報告）
js/main.js              啟動、data-bind 雙向綁定、重算、左右兩欄渲染、⋯選單
tools/smoke.js          Node 執行的端到端斷言（20 項，含報告與渲染輸出的防線）
tools/checkall.sh       每個檔案 node --check ＋ 離線、ES5 風格、單一主題與代號外洩檢查
docs/SPEC.md            建置契約
docs/UI-V2.md           介面契約（覆蓋 SPEC 第 8 節）
docs/DATA-VERIFICATION.md  查證清單 ← 上線前必讀
docs/KNOWN-ISSUES.md    已知問題與狀態
docs/DEPLOY.md          部署與擴充指引
```

技術限制（`tools/checkall.sh` 每次都會驗）：純靜態、無建置步驟、無 ES Module、
無 `fetch`／`XMLHttpRequest`／`WebSocket`／`sendBeacon`、無外部 CDN、
圖表全部手寫 inline SVG、語法限 ES5 風格、引擎層不得觸碰 DOM 與 localStorage、
介面上不得出現引擎內部的代號、全專案不得出現 `prefers-color-scheme`。

驗收指令：

```
node tools/smoke.js      # 20 項斷言，全過才算數
bash tools/checkall.sh   # 靜態檢查，含上面那串限制
```
